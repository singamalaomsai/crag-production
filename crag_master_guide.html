Corrective RAG (CRAG) Production Master Blueprint

Complete Systems Architecture, Execution Steps, Line-by-Line Codebase Analysis, and Enterprise Application Guide

1. Executive Overview & Problem Statement

Standard Large Language Models (LLMs) operate in a closed-book manner where responses are generated strictly from static neural network weights frozen during training[span_0](start_span)[span_0](end_span). This creates three primary failure modes in mission-critical deployments:

  • Parametric Hallucination: Models present fabricated answers with high linguistic confidence when internal knowledge is absent[span_1](start_span)[span_1](end_span).
  • Data Staleness: Models lack access to recent data or evolving facts without costly fine-tuning[span_2](start_span)[span_2](end_span).
  • Information Boundaries: Standard models cannot access private enterprise documents, internal wikis, or engineering manuals[span_3](start_span)[span_3](end_span).

Naive RAG attempts to resolve this by retrieving nearest neighbors from a vector store and injecting them into the prompt. However, when the retrieval engine retrieves noise or misses relevant chunks, standard RAG still produces hallucinations[span_4](start_span)[span_4](end_span). Corrective RAG (CRAG) inserts an autonomous evaluator node to evaluate retrieved documents prior to synthesis[span_5](start_span)[span_5](end_span). If local documents are validated, it grounds answers with verified citations; if local context is insufficient, it triggers an autonomous web search fallback[span_6](start_span)[span_6](end_span).

2. End-to-End System Lifecycle & Execution Flow

  1. Document Ingestion & Semantic Chunking: Documents or PDFs are split into sliding windows (128 words, 20-word overlap) with document IDs and token offsets[span_16](start_span)[span_16](end_span).
  2. Hybrid Multi-Index Retrieval: Submits queries in parallel to Qdrant (dense vectors) and BM25 (sparse lexical match), combined via Reciprocal Rank Fusion (RRF)[span_17](start_span)[span_17](end_span).
  3. Cross-Encoder Reranking: Evaluates top-ranked candidates with deep token-level cross-attention to filter false positives[span_18](start_span)[span_18](end_span).
  4. Reflective Self-Evaluation: An evaluator LLM grades each chunk as relevant or irrelevant[span_19](start_span)[span_19](end_span). If zero chunks pass, it flags web_search_fallback = True[span_20](start_span)[span_20](end_span).
  5. Autonomous Web Fallback: If flagged, Tavily executes a public crawl to retrieve real-time external articles into the document pool[span_21](start_span)[span_21](end_span).
  6. Attributed Generation: Synthesizes the final answer using verified context and appends citations like [doc_id] or URLs[span_22](start_span)[span_22](end_span).

3.1 Semantic Chunking Engine (app/retrieval/chunking.py)

01class MetadataChunker:
02    def _init_(self, chunk_size: int = 128, chunk_overlap: int = 20):
03        self.chunk_size = chunk_size
04        self.chunk_overlap = chunk_overlap
05
06    def split_text(self, text: str, doc_id: str):
07        words = text.split()
08        chunks, start = [], 0
09        while start < len(words):
10            end = start + self.chunk_size
11            chunk_text = " ".join(words[start:end])
12            chunks.append({
13                "doc_id": doc_id,
14                "content": chunk_text,
15                "metadata": {
16                    "doc_id": doc_id,
17                    "token_start": start,
18                    "token_end": min(end, len(words)),
19                },
20            })
21            start += self.chunk_size - self.chunk_overlap
22        return chunks

3.3 Decision Nodes & Self-Correction (app/graph/nodes.py)

01import os
02from typing import Dict, Any
03from tavily import TavilyClient
04
05class CRAGNodes:
06    def _init_(self, hybrid_retriever, llm_evaluator, llm_generator):
07        self.retriever = hybrid_retriever
08        self.evaluator = llm_evaluator
09        self.generator = llm_generator
10        self.tavily = TavilyClient(api_key=os.getenv("TAVILY_API_KEY"))
11
12    def retrieve(self, state: Dict[str, Any]) -> Dict[str, Any]:
13        docs = self.retriever.search(state["question"])
14        return {"documents": docs, "question": state["question"]}
15
16    def grade_documents(self, state: Dict[str, Any]) -> Dict[str, Any]:
17        question = state["question"]
18        docs = state["documents"]
19        graded_docs = []
20        needs_web = False
21        for d in docs:
22            score = self.evaluator.evaluate(question=question, context=d["content"])
23            if score == "relevant":
24                graded_docs.append(d)
25        if len(graded_docs) == 0:
26            needs_web = True
27        return {"documents": graded_docs, "web_search_fallback": needs_web}
28
29    def web_search(self, state: Dict[str, Any]) -> Dict[str, Any]:
30        question = state["question"]
31        results = self.tavily.search(query=question, max_results=3)
32        web_docs = []
33        for r in results.get("results", []):
34            web_docs.append({
35                "doc_id": r["url"],
36                "content": r["content"],
37                "metadata": {"title": r.get("title", r["url"])}
38            })
39        return {"documents": state["documents"] + web_docs}
40
41    def generate(self, state: Dict[str, Any]) -> Dict[str, Any]:
42        answer = self.generator.generate(state["question"], state["documents"])
43        sources = [{"doc_id": d["doc_id"], "metadata": d.get("metadata", {})} for d in state["documents"]]
44        return {"generation": answer, "sources": sources}

  • Lines 16–20: grade_documents: Initializes evaluation tracking for the candidate passages[span_41](start_span)[span_41](end_span).
  • Lines 21–24: Iterates through candidate passages, using the evaluator LLM to classify them as relevant or irrelevant[span_42](start_span)[span_42](end_span).
  • Lines 25–26: Sets needs_web = True when zero chunks satisfy the grading criteria[span_43](start_span)[span_43](end_span).
  • Line 27: Updates the active state with surviving chunks and the fallback flag[span_44](start_span)[span_44](end_span).

3.4 Graph Routing & Workflow (app/graph/workflow.py)

01from langgraph.graph import StateGraph, END
02from app.graph.state import GraphState
03
04def decide_to_generate(state: GraphState) -> str:
05    if state["web_search_fallback"]:
06        return "web_search"
07    return "generate"
08
09class CRAGPipeline:
10    def _init_(self, nodes):
11        workflow = StateGraph(GraphState)
12        workflow.add_node("retrieve", nodes.retrieve)
13        workflow.add_node("grade_documents", nodes.grade_documents)
14        workflow.add_node("web_search", nodes.web_search)
15        workflow.add_node("generate", nodes.generate)
16
17        workflow.set_entry_point("retrieve")
18        workflow.add_edge("retrieve", "grade_documents")
19        workflow.add_conditional_edges("grade_documents", decide_to_generate, {
20            "web_search": "web_search",
21            "generate": "generate"
22        })
23        workflow.add_edge("web_search", "generate")
24        workflow.add_edge("generate", END)
25        self.app = workflow.compile()
26
27    def run(self, question: str):
28        return self.app.invoke({
29            "question": question, 
30            "documents": [], 
31            "web_search_fallback": False,
32            "generation": "",
33            "sources": []
34        })
  • Lines 04–07: decide_to_generate: Routes execution to web_search if fallback was flagged, or directly to generate otherwise[span_47](start_span)[span_47](end_span).
  • Lines 11–15: Instantiates StateGraph(GraphState) and registers each step as a named node[span_48](start_span)[span_48](end_span).
  • Lines 17–18: Configures retrieve as the entry point and routes its output to grade_documents[span_49](start_span)[span_49](end_span).
  • Lines 19–22: Sets conditional branching out of grade_documents based on decide_to_generate[span_50](start_span)[span_50](end_span).
  • Lines 23–25: Connects web_search to generate, links generate to END, and compiles the workflow[span_51](start_span)[span_51](end_span).

4. Enterprise Applications & Operational Value

Engineering Operations & Field Maintenance

Field technicians can query equipment symptoms across large service manuals. The system returns explicit repair steps with page citations, helping avoid downtime from inaccurate procedures.

Corporate Policy & HR Helpdesk

Ingests travel policies and employee handbooks. Inquiries regarding limits, reimbursements, or leave receive grounded answers backed by specific policy clauses.

Regulatory & Legal Auditing

Assists compliance officers in validating contracts and disclosures against internal policies and current external regulations via automated web fallback.
